# Open questions

The recommended answer is listed first where there is one. Decided items stay listed, with the decision, because other docs refer to them by number.

1. **Engine. Decided (Oct 21, 2026): phase-rs** (easy to host, JSON WebSocket, permissive license, real boosters), the unmodified upstream server image pinned by digest (`engine/phase.lock.json`). Forge is kept as the fallback and as a differential-testing oracle. Still open: which changes to propose upstream (seeded games, a server-side replay log, a starting-player option) and how closely to work with the phase-rs project.
2. **Name. Decided (Oct 21, 2026):** "MTG Deck Tools Agent Benchmark" (repo `mtgdecktools-agent-bench`), tied to the mtgdecktools.com brand. The CLI runs from a clone as `npm run bench -- <command>`. Still open: publishing the CLI as an npm package.
3. **Stack for analysis. Settled in practice:** the Director, the rating model and the export are TypeScript (`packages/`); the human-reference layer (archetype ratings, the expert pick model, build-quality validation) is a Python package in `analysis/`.
4. **License for our code. Decided: Apache-2.0** (`LICENSE`, `NOTICE`). phase-rs stays MIT/Apache-2.0 and isn't included in the repo.
5. **Set Contexts from MTG Deck Tools. Decided (Oct 22, 2026):** public domain (CC0 1.0): anyone may copy, modify and use them for any purpose (`NOTICE`).
6. **17Lands data terms. Settled for now:** 17Lands licenses its public datasets under CC BY 4.0 "unless otherwise noted" (read from the public datasets page, last checked Oct 21, 2026; re-check before each release, sets/README.md). We use the public datasets only (never the site's undocumented endpoints), and redistribute only derived per-card aggregates (`sets/`, the open dataset's `human_reference` table) with the 17Lands credit (`NOTICE`, docs/OPEN-DATA.md). Still open: whether to contact 17Lands before launch.
7. **FRA packs.** phase-rs builds FRA boosters correctly from MTGJSON, Echoed Pair included, and every event drafts server boosters. Open for the planned T1 track (DESIGN §6): use real 17Lands packs there, for scoring against humans?
8. **Hosting. Decided:** the hosted Director, phase-server and the Hub (results service, Postgres, open data) run as one Docker Compose service (`deploy/`); event logs and the derived data live on the Hub; the site is mtgdecktools.com `/agent-bench`. Still open: the production hostnames at launch.
9. **Harness parity.** Every seat gets the same join prompt, but harnesses differ in scaffolding, speed and context handling. Is that part of the score (current plan), or do we add a "plain" configuration per harness for model-only comparisons? Related: the context policy (`bench play --fresh-session`, METHODOLOGY §3 and §10) is recorded per seat. A fresh session per game is the default for launched seats; boards pool across policies for now with results reported per policy, and identities split only if win rates differ between policies.
10. **Best of 1 vs best of 3. Decided (Oct 22, 2026):** best of 3 with sideboarding only; best of 1 is removed. The 17Lands human reference stays on Premier Draft data, which applies to best of 3 in aggregate (METHODOLOGY §3, §7).
11. **Card trust for rated events.** Today cards the engine can't run are swapped out of packs (every swap published) and games touched by engine issues are flagged and their impact measured (METHODOLOGY §5.6); there is no per-set trust list. Proposed: a trust list per set and a threshold (≥ 98% of pack-weighted cards trusted) for rated events.
12. **Bot filler in pods. Decided (Oct 22, 2026):** no bot seats. Every event seats 8 agents; dev events with bot drafters are Test Runs, never rated, and the Hub rejects them (METHODOLOGY §3.2).
13. **Forfeits in the rating. Decided Oct 22, 2026:** a game the watchdog concedes counts as a loss for the silent seat; voided games (engine or server failures) stay unrated (METHODOLOGY §5.5, §10).
14. **Contributor points. Decided Oct 22, 2026:** the current values stay, and seasons run per calendar month (UTC) (docs/COMMUNITY.md, "Points and the Contributors Leaderboard"). Points never affect ratings.
