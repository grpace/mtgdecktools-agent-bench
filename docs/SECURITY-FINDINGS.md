# Security findings: pre-release audit

This page records the audit done before the repository goes public, on 2026-10-22, at commits `b8e0418`…`eb13789`, and the seat-facing red-team pass that followed it the same day at `6b4f53c` ([SEC-*](#seat-facing-red-team-pass-sec), HUB-22 to HUB-31). The threat model and the controls are in [SECURITY.md](SECURITY.md). Line numbers refer to the code at the time of the audit and will drift; search for the quoted code if they don't match.

**Severity** is how bad the finding is on the hosted stack, given who can reach it:
- **Critical:** anonymous remote compromise or data loss.
- **High:** anonymous denial of service of live events, or stored XSS or file writes from a submission.
- **Medium:** needs a token or unusual conditions, or weakens a control.
- **Low:** defense in depth.
- **Info:** worth knowing; no action needed.

**Status** is one of:
- **Fixed:** the commit is named.
- **Open:** the owner is named.
- **Accepted:** documented and not changing.

## Seat-facing red-team pass (SEC)

The question: if someone tampers with the agents talking to the Director, can the Director be compromised, run scripts or break things? The threat model is a contributor who fully controls one or more seats (any bytes on `/mcp/<token>`, any tool and arguments at any rate, many connections, huge or nested JSON, bad UTF-8, slow clients, concurrent `decide` calls) and their own CLI (bundles, usage summaries, lobby joins). Everything was tested against a local stack only: the pinned phase-server, an unpatched Director and a patched one side by side, and the hosted compose file booted with Podman. The tools are `scripts/security/fuzz-mcp.mjs` (hostile HTTP and MCP traffic; 35 of 50 checks failed on the unpatched Director, 50 of 50 pass now) and `scripts/security/engine-probe.mjs` (illegal structured answers and oversized decks sent straight to phase-server).

**No remote code execution path was found.** There is no `eval`, `Function`, `vm` or dynamic `import` of data; the two child processes (the report export and the Hub's open-data build) run fixed commands with fixed arguments and no shell; nothing an agent sends becomes a file path, a URL the server fetches (so no SSRF) or a deserialized object with behavior; `__proto__` keys are dropped by the schemas; and agents never reach phase-server, which only ever receives actions the Director builds. Tool arguments are validated by zod before any handler runs. What a hostile seat *could* do was deny service and spoil its table's results; those are fixed below.

Also verified, unchanged:
- The seat token is matched strictly before any body is read; unknown tokens are rate limited per address. Racing `decide` calls apply one answer at most.
- `/data` and `/api/events/<id>/files` refuse traversal, encoded dot segments, NUL and dot-files.
- The interim submissions endpoint can't plant a checkpoint (`state.json` isn't an allowed bundle file), so nothing uploaded is ever resumed as a live event.
- phase-server refuses WebSocket messages over 64 KB and decks over 500 cards, and checks every structured action against the game state (SEC-8).
- Prior DIR-1 to DIR-20 fixes are in place (malformed targets answer `400`, bodies over the limit `413` with the connection closed).
