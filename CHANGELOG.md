# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html) for the repository as a whole (the packages under `packages/` share its version). See [docs/RELEASING.md](docs/RELEASING.md) for what counts as a breaking change here.

Comparability is versioned separately and doesn't follow the release version: the MCP protocol (`docs/PROTOCOL.md`), the prompts (`prompts/`, earlier sets in `prompts/archive/vN/`, identified by content hash), the bundle format (`bundle_version`), the export schema (`docs/SITE-DATA.md`) and the booster generator (`BOOSTER_GENERATOR`) each carry their own version. Results record all of them.

### Changed

- **Git deploys** (owner, 2026-10-25): each hosted instance is a Coolify Docker Compose application built from this repository, one branch per instance (`deploy/dev`, `deploy/prod`), deployed on push by the GitHub App's webhook, so deploys work without the workstation (docs/OPERATIONS.md "Deploying").
  - `deploy/compose.yaml` builds the Director image itself, tagged with the deployed commit; `/health` and `provenance.director` report that commit's short sha (`SOURCE_COMMIT`).
  - `deploy/coolify-setup.sh` creates or updates an instance: a verified Coolify DB dump first, the application, secrets as runtime-only Coolify variables, and the nightly `pg_dump` task. `INSTANCE=test` gives a throwaway instance of a work branch, and `--delete` removes it.
  - `deploy/deploy.sh` promotes a commit instead of building on the host. It keeps the CI-stamp gate, the engine and card-override guards and the drains, pushes the commit to the deploy branch (production only takes commits on `origin/main`), follows Coolify's deployment and waits for `/health`. It also has `--ref`, `--rollback` and `--redeploy`, and creates the application on an instance's first deploy. `--allow-dirty` is gone, and `--recover-secrets` moved to `coolify-setup.sh`. `deploy/coolify-service.php` is replaced by `deploy/coolify-app.php`.
  - The Hub reads the Director's booster archive (`HUB_BOOSTER_ARCHIVE_DIRS`, on the hosted stack `/director-cache/booster-archive`), so events from before an engine upgrade keep passing pack regeneration with no copy step at deploy.
  - Compose defaults now ship with their commit: Coolify leaves those variables empty.
  - `card-data` exits at once on SIGTERM; it used to hold every deploy for Coolify's 30-second stop grace.
  - Tested on a throwaway instance: a mid-game deploy by push, with the event resumed, finished and verified by the Hub; `/health` down 19 s.

- **Best of 3 with sideboarding, the only format** (owner decision, 2026-10-22). Before games 2 and 3 of a match the loser of the previous game chooses to play or draw (`play_draw` decision; after a drawn game the previous chooser; game 1 from the event seed), then both seats sideboard at the same time (`sideboard` decision): the current deck and the whole sideboard as card JSON, as at deckbuilding, plus the match memory; answer `keep` or the whole deck again, validated exactly like deckbuilding (pool cards only, copies drafted, basics unlimited, at least 40). Neither seat sees the other's changes, only the deck size; each match starts from the registered deck; an inactive seat keeps its deck and plays first. phase-server rolls its own starting player, so the Director creates a new game until the chosen player is on the play (about 50 ms each, before any decision is offered). Logged as `play_draw_offered`, `play_draw`, `sideboard_offered`, `sideboarded` (with `in`/`out` swaps), `game_start.deck_sizes`/`starter`, `event_start.sideboarding`; a resumed event reuses what the log holds. Spectators see "Sideboarding…" and the deck size after the broadcast delay; the swaps are released with the decklist when the seat has no games left. The Hub verifies both (`games.sideboarding`, `games.play_draw`). Seat protocol 0.3 (docs/PROTOCOL.md §3.3). - **Flaky test:** the spectator replay limit test (SEC-1) is deterministic: `SpectateHub` takes injected clocks (`now`, `sliceClock`, `yieldTurn`), the test holds the first replay at a yield while the other nine requests arrive, checks the per-minute budget on a frozen clock and its refill, that a replay yields at least every 20 lines, and the 30 s give-up, which used to fire on a loaded machine.

- **Scripted players counted as LLM agents** (critic review C-1): seats were classified by name, so neutral hosted names (`seat-<hex>`) made a table of 8 `script/random` seats count as 8 LLM agents in home totals (72 games and 8,200 decisions instead of 46 and 4,413), the FRA set findings, What's New, the main board's selection and the Hub's "rated table" count. Seats are now classified from `event_start` metadata (`isLlmSeat`); regression test on the real table `2026-10-22-22-34-06-fra-905e`. A rated table needs at least one rated game.
- Home totals count settled events only, like the open data.

- **The season rolls over at the month boundary** (F-4): the Hub rebuilds the contributor boards a few seconds after 00:00 UTC on the 1st (and `/api/contributors` rebuilds a view from an earlier month), so November shows from November 1 without waiting for a table. Clock-mocked tests.
- `scripts/bench/test/setup-e2e.sh` answers the Make Your Table Count prompt and requires the hand-off to be accepted; it runs in `scripts/ci-local.sh --full` (podman). `packages/director/test/hosted-e2e.sh` expects the 401 and is a release check (docs/RELEASING.md).

- **Infrastructure failures never decide a match** (LAUNCH-CHECKLIST D-1). A game the engine can't start is now voided and replayed like one it lost (it used to end the match at once), with pauses of 2 s, 30 s and 2 minutes before the replays. A game voided four times ends its match with **no result** (`match_end.no_result`, `reason`): no winner, no Swiss points for either seat (the pair counts as met), not a win, loss or draw in the standings, the outcomes or the head-to-head records; the games it finished stand. The void count and a no-result ending survive a restart; the Hub's game check and Swiss regeneration read the flag; export `MatchSummary.no_result`. METHODOLOGY §3.2 "No result".
- **Deploys mid-event** (D-2): after a restart the Director retries each game's reconnect with backoff for about 105 s (`game_reconnect_retry`) instead of voiding after one refused try; the `bench` CLI treats the proxy's 404, 502 and 503 during a restart as "no answer yet" (only the Director's own JSON 404 means an event is gone), waits up to 10 minutes (`MTGDT_DIRECTOR_WAIT_MIN`) with backoff, and relaunches a seat session that ended meanwhile without counting it; the scripted agent retries its connection and calls for 10 minutes; the inactivity watchdog pauses while the Director shuts down and gives every seat at least 15 minutes after a resume; the Director starts once phase-server is healthy.
- **Engine upgrades vs live events** (E-2): a resumed event regenerates its packs from the booster data it started on (the Director archives the data it runs on by hash at every start, `director-cache/booster-archive`), not from the new build's, which made it fail as `resume_failed`; `event_resume.provenance` records the engine and card data from then on; the Director's unsupported-card list is rebuilt when the card data changes. `deploy.sh` refuses an engine change while events are live unless `--drain-events [minutes]` waits until none is (running events play on; `POST /api/admin/drain {"games": false}`) or `--force`, and stops when the booster archive in the Hub fails.
- **`deploy.sh` never regenerates a secret** (H-2): secrets are generated only when the service is created; a missing one on an existing service stops the deploy, and `--recover-secrets` copies it back from the running containers without printing it.
- **`--seat …/ultra` and lobby knowledge names:** a seat spec may end with any effort level the registry knows (Codex's `ultra` was read as part of the model), and `bench lobby join --knowledge` takes the same names as `bench new` (`set-context`, `context+stats`, …) instead of sending them on to a 400.
- **`bench play` waits while the hosted table is at capacity:** an event in the Director's queue gets no harness sessions until it starts (they used to start at once and poll, paid, for up to 4 hours). It says the queue position as it changes, and stops if the event times out in the queue.
- `bench play` stopped by a signal (SIGTERM, SIGINT) now waits for its seats' sessions to end and cleans up like a normal exit: sign-in copied back, session record saved, the seat's temp folders and its Claude Code project folder (`~/.claude/projects` or `$CLAUDE_CONFIG_DIR/projects`) removed. A stopped `play` no longer relaunches sessions.

- **The lobby's `recent[]` lists every Private Table,** as docs/LOBBY.md says: tables created with the admin token were missing (the first hosted 8-seat test table among them). They are listed with no contributor and never count in contribution stats; scripted-only tables (smoke and load tests) stay out.
- **CLI on hosted admin tables.** `bench status` sends the token this machine has for the event (the admin token for a table created with it, the contributor token for a hosted contributor table) and shows the organizer's view, or says when it only got the public one. `bench play` on a hosted Director says the results go to the Hub on their own instead of suggesting `pull && bundle`, waits for the event to end before sending its seats' usage, and stops a seat's session that is still running 2 minutes after the Director called the seat done.
- **A seat with no games left stops at once.** On the first hosted 8-seat table, seats whose matches were over kept calling `wait_for_decision` until the last match of the event ended: about 14–19 minutes and 20–27 calls each, $5.37 of the $56.37 (9.5%). When a seat's last match ends (or it has a bye in the last round), the Director answers at once with `EVENT COMPLETE. You're done: no more games for you in this event; you can stop now.` and that seat's own results, logs `seat_done`, and the event status shows the seat as done, so `bench play`, `scripts/play-claude-seat.sh` and the watchdog treat it as finished, never as a disconnect. A finished seat that keeps calling is answered at the pace of a normal wait.
- **Seat names never name a model.** `bench new` named seats after their model (`claude-haiku-5-5-2`), and those names reached the anonymous `/api/events/<id>`, the live stream and the logs. Every table now uses neutral `seat-<hex>` names like the lobby: `bench new`, `bench setup`, the admin API (which replaces any other name for a seat with a harness or model and says so in `renamed`) and one-shot `--agents`. The model stays in the seat metadata only.
- **Spectator stream: results wait for the broadcast delay.** `standings` went out at 0 s on the first hosted 8-seat table, about 90 s before the delayed `game_over`; standings, a seat's done status and its identity release now come after the delay, with the results they follow (docs/SPECTATING.md).
- **Token and cost estimates re-measured** on the first 8-seat hosted table (8× Claude Haiku 5.5 at low effort, best of 1: $56.37, 69 to 169 M cache reads per seat, against the documented 20 to 120 M). The Confirmation now prices each seat at its model's list price (with the providers' long-context prices; Claude Haiku 5.5 is 5× above 100 k tokens, which almost every call is) and adds up the table, says what is measured and what is projected, and projects best of 3 from a call-by-call token model (`scripts/bench/estimate.ts`) instead of a flat $3 to $35 per seat. The estimates leave out the 9.5% ($5.37) that finished seats spent waiting for the event to end. Per-tier tables in docs/HARNESSES.md and docs/COMMUNITY.md.
- **`decide` never drops part of an answer.** With `option` and `blocks` or `attackers` both given, the option ran and the list was ignored (the first 8-seat hosted test table: a seat's 6 blocks were cut to the option's 1, about 10 times in one event). A structured answer now wins when it agrees with the option and is refused when it doesn't; fields a decision doesn't take are refused, never ignored (draft picks, deckbuilding, the deck review and games alike). docs/PROTOCOL.md "Answers are applied whole or not at all".
- **No phantom models from seat names.** The export took a seat's model from its name minus a trailing "-<n>", so a seat named `claude-haiku-5-5` became `claude-haiku-5`, with its own legacy leaderboard row. A seat's model now comes from its metadata (`model_id`, else `model`); only an old log without metadata falls back to the seat name, and only to a name the registry knows (the whole name, else without the "-<n>"); anything else is "unknown".
- **Tables of one setup are not "Rated".** An 8-seat table where every seat was the same model, harness and effort has no rated games, but its event read as rated. Export 2.11 adds `EventSummary.rating_status` ("Rated" only with rated games; "No Rated Games" with the reason "all games were between identical setups"; "Not Rated"), says the same in a board row's `provisional_reasons` (was "no LLM-vs-LLM games"), and exports Swiss finishes per setup for the event, the group and summary.json's board lines whether or not any game was rated (docs/SITE-DATA.md v2.11).

### Security

- **Network separation under Coolify** (LAUNCH-CHECKLIST H-8): Coolify puts every container on the service's project network too, where the Hub was in fact reaching Postgres. phase-server and Postgres now listen only on their private network's address, found at start from a network-scoped alias (`phase-server-engine`, `hub-db-internal`; `--bind`, `listen_addresses`), and refuse to start without it; the Director and the Hub connect through those aliases. Postgres gets its own pg_hba.conf (`-c hba_file`, so the existing volume uses it): the hub role from the `db` subnet with `scram-sha-256`, the local socket for `docker exec` (healthcheck, `pg_dump`, restores), every other host rejected; `password_encryption=scram-sha-256` (the hosted role's password already is). `scripts/image-check.sh` adds a shared network like Coolify's (`deploy/compose.ci.yaml`) and fails if either service listens on it or the pg_hba rules change. OPERATIONS "Networks".
- **One scrubber for every public output** (B-3): `packages/director/src/public-text.ts` now scrubs the Hub's `/data` export and stored run folders, the Director's own `/data`, the spectator stream and replays, as well as open data, and catches more: API keys (Anthropic, OpenAI, GitHub, AWS, Google, Slack, Stripe, Hugging Face), PEM keys, named secrets, long high-entropy strings, JWTs, IPv6 addresses, `$HOME`, UNC and forward-slash Windows paths. Tested against fixtures, all 36,004 cards' text (unchanged) and 11k local agent texts (no false hits). Open-data logs are rebuilt once (`LOG_VERSION` 2); run `npm run hub -- reingest` after deploying so stored run folders get it.
- **Takedowns reach hosted Directors** (B-4): a Director reads the Hub's moderation list (`GET /api/internal/moderation`, every minute and on `POST /api/admin/moderation/sync`), deletes a taken-down event's run folder and exported files, and leaves it out of `/api/events`, `/data`, the stream and replays; the list survives restarts.
- **GitHub account age** (HUB-7): `HUB_GITHUB_MIN_ACCOUNT_DAYS` defaults to 30 in code, as on the hosted Hub. More handles are reserved (`erased-`, `moderator`, `mtgdt`, `support`, …).

- **The bench CLI no longer trusts the Director** (audit CLI-1): event ids, seat names and seat URLs are checked before they name a file or a server, and paths must stay inside the run folder. What starts each seat comes from this machine: the confirmed plan (`confirmation.json` → `launch`, checked by `bench play`) or the seats a lobby ticket joined with. A fired lobby table with other seats is refused.
- **Harness isolation** (CLI-2): every seat `bench play` starts gets a private config folder with only its `mtg` server (the seat URL is no longer in argv). Codex runs with its own `CODEX_HOME` and the shell, web search and image tools off; Gemini CLI with its own `GEMINI_CLI_HOME` and no `--approval-mode yolo`; OpenCode with its own config folder, every non-`mtg` tool denied and no `--auto`; Cursor with its own `HOME`; Claude Code adds `--restricted` and leaves global `CLAUDE.md` out. ## [0.1.0] - Unreleased

First public release: the working prototype of the benchmark and the community kit. Dated when it is tagged.

### Added

- **Director** (`packages/director`): a bridge from the phase-rs rules engine (`phase-server`, pinned by digest in `engine/phase.lock.json`) to one MCP endpoint per seat.
  - **Full events:** an 8-seat booster draft of a retail set, 40-card deckbuilding, and a best-of-3 round-robin between agent seats, with draft bots filling empty seats.
  - **Decisions as text:** every decision is presented as readable text with labeled options, including manual mana payment, alternative costs (warp, evoke, overload, bestow), crew and optional costs, and mana-color labels. Refused actions are hidden.
  - **Knowledge levels:** Set Contexts fetched from mtgdecktools.com, with their source and sha256 logged.
  - **Prompts:** Limited fundamentals, a deckbuilding guide and a pool analysis for every seat.
  - **Server mode:** many concurrent events and a token-protected admin API.
  - **Logging and provenance:** turn snapshots, end reasons, engine and Director provenance (Director versions built from uncommitted changes are tagged `-dirty`), and booster provenance (`event_start.boosters`).
  - **Seat reliability:** an inactivity watchdog forfeits the decisions of silent seats, seat sessions that exit early are relaunched, and idle seats are told what is left in the event.
  - **Engine-issue flags:** unimplemented effects and agent `report_rules_issue` reports are flagged (METHODOLOGY §5.6).
- **Spectator stream:** a live SSE and polling view of every event under a fairness policy (`docs/SPECTATING.md`). Picks are held until their round ends; notes are delayed and hidden cards blanked; hands and decklists are held until the seat has no games left. It has per-IP, per-event and total limits.
- **Community kit:**
  - `npm run up` self-hosts the engine and the Director (compose or plain podman/docker).
  - The `bench` CLI runs `new`, `play` (headless seats with relaunch), `seats`, `status`, `pull`, `bundle` and `submit`.
  - Results bundles are flat `.tar.gz` files with a manifest of sha256 hashes and per-seat usage.
  - Harness launchers are included for Claude Code and other MCP clients (`docs/HARNESSES.md`).
- **Hub** (`packages/hub`): the central results service, with a Postgres index, a content-addressed bundle store and the integrity checks in METHODOLOGY §3.1.
  - **Integrity checks:** draft and game consistency, pack regeneration from the seed, provenance, duplicate decision streams and latency/usage anomalies.
  - **Review and admin:** a review queue, takedowns, an admin API and CLI, and contributor and service tokens stored as sha256.
  - **Export:** an incremental JSON export at `/data` with ETags and gzip.
  - **Hand-off:** hosted Directors hand off finished events (`POST /api/internal/events`) with retries.
- **Report site and data export** (`packages/site`): a static HTML report and a versioned JSON export (schema v2, `docs/SITE-DATA.md`) for mtgdecktools.com.
  - Bradley–Terry ratings with cluster-bootstrap intervals and stage scores.
  - Live redaction of running events.
- **Analysis** (`analysis/`): context-aware draft evaluation, made of archetype-conditional 17Lands ratings, an expert pick model and a run scorer.
- **Methodology and docs:** METHODOLOGY (model vs model only; harness failures are never scored as misplays), PROTOCOL, ARCHITECTURE with measured capacity, COMMUNITY, HARNESSES, SPECTATING and UPGRADING.
- **Operations:**
  - Engine upgrades go through `scripts/upgrade-phase.sh` (probe, smoke-test, then pin).
  - Coolify deployment uses `deploy/deploy.sh`, with secrets generated locally and never printed.
  - `scripts/load-test.sh` load-tests the stack, and `scripts/smoke-event.sh` runs a scripted-agent smoke test.
- **Release engineering:**
  - GitHub Actions CI: typecheck, unit tests, and a scripted smoke event plus the Hub end-to-end test against the pinned engine and Postgres.
  - Issue and pull request templates, this changelog, `docs/RELEASING.md`, `CODE_OF_CONDUCT.md`, `docs/SECURITY.md` and `docs/SECURITY-FINDINGS.md`.

### Security

- Pre-release audit of every exposed surface: see [docs/SECURITY-FINDINGS.md](docs/SECURITY-FINDINGS.md).
- **Hub bundle intake:**
  - Decompression bombs are refused (`HUB_MAX_UNPACKED_BYTES`).
  - Ill-typed or oversized log content is rejected before export (`packages/hub/src/sanity.ts`). This closes stored XSS through set codes and numeric fields, path traversal through set codes, and a memory blow-up at Hub start.
  - Export writes are confined to the served tree.
- **Hub HTTP:**
  - Oversized chunked bodies are cut off.
  - Malformed `/data` paths answer 404.
  - Every response carries `nosniff`, and there is a headers timeout.
  - A stream error no longer crashes the process.
- **Site loader:** it drops events with unsafe ids or set codes, coerces numbers, escapes navigation links and uses bounded regexes. With `SPECTATE=admin|off`, running events stay out of the public export.
- **Tokens:**
  - The `bench` CLI refuses to send tokens over plain HTTP to non-loopback hosts.
  - `new-event.sh` keeps the admin token out of `ps`.
  - `deploy.sh` never syncs `.bench/` or `.env*` and writes its Coolify DB dump with `umask 077`.
