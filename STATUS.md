## How we work
- **CI is local while the repo is private** (GitHub Actions minutes). Before pushing code: `scripts/ci-local.sh --quick`. Before deploying: `scripts/ci-local.sh --full` (it writes `.ci-local/<sha>.json`, and `deploy/deploy.sh` refuses a commit without a passing full stamp). "Keep CI green" means the local CI. Weekly: `npm run deps -- check`. Details in docs/RELEASING.md.
- **Deploy** only pushed commits with a full CI stamp: `INSTANCE=dev deploy/deploy.sh --drain` when nothing is live. It pushes the commit to the instance's deploy branch and Coolify builds it from GitHub, so uncommitted edits never ship (OPERATIONS "Deploying"). Never deploy production mtgdecktools.com, and move `deploy/prod` only on the owner's go.
- **Commit your own paths only**: several agents share this working tree. Fast-forward only on `main`.
- **Don't spend model tokens to test plumbing:** use the scripted agent (`scripts/mcp-random-agent.mjs`, harness `script/random`). Our own LLM runs are pipeline tests only; the community runs the benchmark.
- **Copy rules:** US spelling; "Set Context" in reader-facing text (the internal key stays `primer`); never "maintainers"; no prompt version labels in reader-facing text; Title Case in the site UI; no npx command until the npm name is claimed.

## How to run

```bash
podman start mtgdt-phase          # or see CONTRIBUTING.md to create it
npm install
npm run up                        # the local stack (Director + pinned phase-server), docs/COMMUNITY.md
npm run bench -- new --set fra --seat "8x script/random" && npm run bench -- play <event>   # a free scripted table
scripts/smoke-event.sh            # conformance smoke: 8 scripted agents, best of 3 with sideboarding (~8 min)
node scripts/peek-seat.mjs <seat-url> [option]                                              # debug a seat
```

Data files (gitignored, in `data/`): `card-data.json` and `draft-pools.json` (copied from the phase-server container) and `unsupported-cards.json`. Runs land in `runs/<event-id>/` (gitignored): `events.jsonl` (every record, including the full text each agent saw), `summary.json`, `seats.json`, transcripts and session files.

## Gotchas learned the hard way
- phase-server silently drops frames over **30/s per socket**. The Director spaces sends at least 60 ms apart and resends on timeout.
- phase-server's protocol version must match **exactly** (pinned in `engine/phase.lock.json`; upgrade with `npm run deps -- update phase`, docs/UPGRADING.md).
- Multi-face cards go to phase-server by **front-face name**.
- Don't `pkill -f`/`pgrep -f` a pattern your own shell's command line contains (it kills itself, exit 144). Kill by PID or port, or use the bracket trick `pgrep -f '[m]cp-random-agent'`.
- Never let two phase-server containers share one data volume (SQLite "database is locked").
- Never edit a shell script while it runs: bash reads scripts lazily, so every script wraps its body in `main()`.
- A game ends when *either* socket reports game over; the other may still deliver older updates. Games ignore updates after a result.
- A deploy restarts the whole stack (Coolify builds, then stops and recreates every container, phase-server too): live events checkpoint on SIGTERM and resume (games re-attached within phase-server's 120 s grace, otherwise voided and replayed; tested mid-draft and mid-game, OPERATIONS "A deploy while events are live"). For an engine change use `deploy.sh --drain-events`: it refuses one while events are live otherwise.
- Run long jobs in the background and poll.
- Coolify's nightly Docker cleanup deletes unused image tags: roll back by moving the deploy branch back (`deploy.sh --rollback --ref <sha>`), not by retagging.

## Hosting notes
- One host, `gr3g-server` (10.1.10.101). Coolify v4 at coolify.greg.tech (behind Cloudflare Access; API only from the LAN). Coolify deploys each instance from its git branch; `deploy/coolify-setup.sh` configures the application through `php artisan tinker` over SSH (no API token) and backs up the Coolify DB first. The Coolify API answers only from 10.1.10.0/24, so remote deploys are a git push or the Coolify UI.
- `*.dev.greg.tech` hosts need no DNS work (DNS-only, not proxied, so long-polls are fine; no CDN). Traefik timeouts are 10 min.
- Secrets live in Coolify's variables, with a copy in `~/.config/mtgdt/` (`-prod/`) on the owner's workstation (generated once by `deploy/coolify-setup.sh`, mode 600, never printed). Never regenerate `contributor-salt` (it re-keys every contributor in the exports), and never change `hub-db-password` without an `ALTER USER`.
- Coolify's own e-mail notifications don't work (SMTP times out behind Cloudflare). Alerts go through Postal on the host instead, like the server's other checks: `~/documents/agent-bench-ops/ops-check.sh` from the grpace crontab (docs/OPERATIONS.md "Monitoring").
